# Learning roadmaps

A roadmap answer is long on purpose: the owner wants stages, free material with links, and a short explanation of why each stage comes where it does. Build it from the curated lists the owner starred on GitHub, so every link is to a known, free, maintained source.

## How to do it

1. Ask at most 2 questions if needed: current level, and hours per week. Otherwise assume a beginner with about 8 hours a week.
2. Pick the backbone list for the subject from `curated-sources.md` (for example OSSU for computer science, developer-roadmap for a job role).
3. Split the path into 4 to 7 stages. Each stage gets: the goal in one line, 2 to 4 resources with links, one small project, and a rough time.
4. Prefer free books and courses (see `curated-sources.md`). Give the exact link to the list section, not just the repo.
5. Add one "build it yourself" project per stage from build-your-own-x when one fits (see `projects-and-practice.md`).
6. For ML and LLM paths, follow the order in `ml-and-llm-path.md`: maths and Python, classic ML from scratch, deep learning, then LLMs from scratch, then shipping models.
7. End with how to check progress: one question per stage the owner should be able to answer.
8. When the answer is long, offer to save it as a PDF or Word file.

## Rules

- Link only to sources you know exist. If unsure, link the list's main page and say so.
- Never invent course names, prices or durations. Say "about" for time estimates.
- Keep each stage short. The detail lives behind the links.
- Free first. Mention a paid course only if the owner asks.
