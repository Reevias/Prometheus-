# Projects and practice for each stage

A stage without a project is easy to forget. Give one small, finished project per stage, sized to a weekend or two.

## Build your own X

**build-your-own-x** (github.com/codecrafters-io/build-your-own-x) lists step-by-step tutorials for rebuilding well-known software from scratch: a shell, a database, a Git, a web server, a programming language, a neural network, a search engine, a regex engine, a 3D renderer and more, in many programming languages. Match one to the stage:

- Programming basics: a command-line tool or a text adventure.
- Data structures and algorithms: a regex engine or a key-value store.
- Operating systems and systems programming: a shell, then a tiny operating system.
- Networks: a web server, then a BitTorrent client.
- Databases: a small SQL database.
- Compilers: an interpreter for a tiny language.
- Machine learning: a neural network from scratch.

Link the exact section of the list, and say which language the tutorial uses.

## Exercises

- Pair each stage with the exercises from its main course (OSSU lists them per course).
- For interviews, add the practice questions in system-design-primer.

## Reading papers

Use papers-we-love only in later stages. One paper per stage at most, with one sentence on why it matters. Suggest reading the abstract, the figures and the conclusion first.

## Checking progress

At the end of each stage, give the owner one question they should now be able to answer, and one thing they should be able to build without a tutorial. If they can't, the next stage waits.
